# 10 実装計画（Claude Code 向け）

版：v1.0-draft｜2026-09-07｜前提：Claude Design で生成した画面（DESIGN_BRIEF・03）を取り込みつつ、以下のマイルストーン順に実装する。各 M は「動く状態」で区切り、E2E テストを通してから次へ進む。

## 0. 開発ルール
- モノレポ（pnpm workspaces）。`apps/web`, `apps/worker`, `packages/core`, `packages/db`。
- 型は Supabase 生成型＋`packages/core/types.ts`。any 禁止。
- 各 Server Action は `zod` で入力検証。
- 各ジョブは冪等（同じ payload で再実行しても壊れない）。
- プロンプトは `.md` ファイル、バージョンはファイル名（`*.v1.md`）。変更時は新バージョンを追加し旧版を残す。
- テスト：Vitest（core）、Playwright（主要フロー）。LLM 呼出はモック可能に。
- 【仮置き】値は `packages/core/config.ts` に集約し、`settings` テーブルで上書き可能にする（11 決定管理表と 1:1）。

## 2. 依存と並行
- M1 と M2 は並行可（別ブランチ）。M3 は M1・M2 の両方に依存。M5・M6 は M3 完了後に並行可。M7 は M4 に依存。
- Claude Design の画面生成は M0 完了時点で開始し、M1 以降の各画面実装時に取り込む。

## 3. 各 M の最初のタスク（Claude Code が着手時に読む順）
1. `CLAUDE.md` → `docs/00_README.md` → 該当 M の FR（02）→ 画面（03）→ データ（04）→ API（06）→ Organize（07、M3 以降）
2. 実装前に `docs/11_決定管理表.md` の【仮置き】値を `packages/core/config.ts` に反映しているか確認
3. 実装後、DoD を満たす Playwright テストを追加して完了

## 4. リスクと対策
| リスク | 対策 |
|---|---|
| Organize の品質が低く、専門家の確認負荷が上限を超える | M3 で専門家 1 名分の実データで早期に試し、prompt v2 を作る猶予を確保。確信度閾値で確認対象を絞る |
| 文字起こし・動画のコスト超過 | 上限（settings）で停止。O04 でコストを可視化 |
| Slack/Gmail の審査・権限で遅延 | 開発用ワークスペース／テストアカウントで先行。M6 を後ろに配置 |
| 評価セットのリーク | Organize クエリで `is_eval=false` 強制。ユニットテストで担保 |
