# 04 データモデル（Postgres / Supabase）

版：v1.0-draft｜2026-09-07｜対象：Claude Code（マイグレーション生成）
方針：DB が知識の正本。Obsidian Vault は Batch 締め時のスナップショット（エクスポート）。全テーブルに `expert_id` を持たせ RLS で分離する。

## 1. ER 概要

```
profiles ──< expert_profiles ──< sources ──< chunks ──< note_sources >── notes ──< note_reviews
                │                 │                              │
                │                 └── transcripts                ├──< conflicts
                │                                                └── vault_snapshots (per batch)
                ├──< batches ──< consultations ──< expert_answers
                │       │
                │       └──< agent_answers ──< evaluations
                │                  │
                │                  └── blind_pairs ──< blind_judgements (reviewer)
                ├──< work_logs
                ├──< oauth_connections
                └──< jobs / cost_logs
eval_sets ──< consultations(is_eval=true)
domains (master), settings (operator)
```

## 3. RLS 方針
- expert：`expert_id = 自分の expert_profiles.id` の行のみ SELECT/INSERT/UPDATE。
- reviewer：`blind_pairs`・`blind_judgements` のうち `reviewer_id = 自分` のみ。`consultations` は pair 経由の question のみ（VIEW `reviewer_pair_view` で必要列に限定）。notes/chunks/sources へのアクセスなし。
- operator：全テーブル SELECT/UPDATE。`pii_maps` と `oauth_connections.encrypted_tokens` は operator も復号値を UI に出さない。
- Storage：バケット `sources/{expert_id}/…`、`vaults/{expert_id}/…`、`audio/{expert_id}/…`。パスの expert_id と JWT のクレームで制御。

## 4. インデックス
- chunks(expert_id, source_id)、chunks embedding ivfflat（cosine）
- notes(expert_id, layer, review_status)、notes embedding ivfflat
- consultations(expert_id, is_eval, batch_id)
- agent_answers(expert_id, batch_id, consultation_id, pipeline) unique
- evaluations(agent_answer_id, expert_id) unique
