# 09 非機能要件・セキュリティ（PoC 水準）

版：v1.0-draft｜2026-09-07

| 項目 | 要件 | 実装方針 |
|---|---|---|
| 機密性・データ分離 | 専門家の元データ・Vault は本人と operator のみ閲覧。専門家間で完全分離 | 全テーブル expert_id＋RLS。Storage はパス＋ポリシー。reviewer はビュー経由で question のみ |
| 知識の非露出 | 知識層と回答生成層を分離。根拠表示は expert/operator 限定 | `packages/core/answer` を唯一の生成入口に。引用はロールで API 層からも除外 |
| Obsidian の内部化 | Vault はサーバー側で生成・管理。専門家端末に Obsidian を入れない。Markdown 記法を UI に出さない | Vault は Storage の zip。UI は notes.structured を描画 |
| OAuth トークン | 最小権限スコープ。暗号化保存。PoC 終了時に失効・削除 | pgsodium で暗号化。S08「切断」で revoke API 呼出→ status=revoked |
| 取込範囲 | 専門家が指定した範囲以外は取得しない | import_scope を保存し、Worker はそれ以外を要求しない。上限超過は停止 |
| 個人情報 | 第三者 PII の匿名化を取込時に選択 | anonymize ジョブ、pii_maps は本人/operator のみ。Slack/E-mail は既定 ON |
| 音声・動画処理 | 精度（修正率）とコスト（時間・費用）を形式別記録。長尺は分割・再開可能 | transcripts.edit_ratio、cost_logs、partIndex 単位の再試行 |
| 再現性 | 同一 Batch・同一相談で再生成可能。モデル・プロンプト・Vault バージョンを記録 | gen_meta、vault_snapshots、prompt ファイルのバージョン命名 |
| 可観測性 | 各処理の入出力・所要・コストを operator が確認できる | jobs / cost_logs、O04 画面、Sentry |
| 可用性・性能 | PoC 水準。同時利用 ≤10 名。画面応答 2 秒以内（生成系はジョブ化） | LLM 呼出は Worker 側。ページは SSR＋ポーリング 5 秒 |
| 運用 | 手動運用・手厚いサポート許容。セルフサインアップ無し | operator 招待、O02 |
| データ削除 | 専門家の指示で削除。論理削除→30 日後物理削除【仮置き】 | requestDataDeletion → status=deleted → 定期ジョブで purge（Storage 含む） |
| バックアップ | Supabase の日次バックアップ（PITR は不要） | — |
| 監査 | 評価セットのロック後編集不可、評価・レビューの変更履歴 | eval_sets.locked、note_reviews/evaluations は追記型 |
| 法務 | 専門家との PoC 参加合意書（データ取扱・第三者情報・成果物の帰属）を準備 | 法務事項は開発外。11 決定管理表 D-14 |

セキュリティ実装チェックリスト（Claude Code が実装時に満たすもの）
- service role key はサーバー（Worker / Route Handler）のみ。クライアントに露出しない
- 全 Server Action で `getSessionRole()` を先頭で呼び、ロール不一致は 403
- RLS を無効化するテーブルを作らない。マイグレーションで `enable row level security` を必ず付ける
- Storage の signed URL は 10 分有効
- OAuth state は HMAC 署名＋有効期限 10 分
- ログに PII・トークン・本文全文を出さない（先頭 200 字まで）
