# 08 評価・計測設計（Measurement Spec）

版：v1.0-draft｜2026-09-07｜目的：第2章の指標と仮説 H1〜H6 を、DB から機械的に集計できる形に定義する。

## 1. 指標定義（SQL レベル）

| 指標 | 定義 | 集計単位 |
|---|---|---|
| avg_score | evaluations.score の平均（pipeline=structured, is_eval=true） | expert × batch |
| pass_rate | score ≥ 4 の件数 ÷ 評価件数 | expert × batch |
| score1_rate | score = 1 の件数 ÷ 評価件数 | expert × batch |
| score_dist | score 1〜5 の件数 | expert × batch |
| tag_dist | deduction_tags の展開集計（unnest） | expert × batch |
| blind_win_rate | blind_judgements で「Agent 側が a/b の優」＋tie の件数 ÷ 判定件数 | expert × batch |
| work_hours | work_logs.seconds の合計 ÷ 3600、type 別 | expert × batch（期間で紐付け） |
| input_profile | sources を type 別に count、chunks.token_count の合計、confirmed expert_answers 件数 | expert × batch |
| transcript_edit_ratio | transcripts.edit_ratio の平均、source type 別 | expert |
| cost | cost_logs.cost_usd の合計、provider/model 別 | expert × batch |
| h3_delta | structured の avg_score − raw_rag の avg_score（同一 batch・同一評価セット） | expert × batch |

目標判定（Batch 最終）：avg_score ≥ 4.0 かつ pass_rate ≥ 0.70 かつ score1_rate < 0.05。blind_win_rate ≥ 0.40 は補助。

## 2. 仮説と集計の対応

| 仮説 | 検証データ | 判定の目安【仮置き】 |
|---|---|---|
| H1 | Batch 最終の主指標 | 目標値達成 |
| H2 | Batch0（既存データのみ）vs Batch1 の avg_score | +0.5 以上の上昇、または pass_rate +20pt |
| H3 | h3_delta（各 Batch） | structured が +0.3 以上 |
| H4 | Batch0→1→2→3 の avg_score | 単調増加（減少 Batch がない） |
| H5 | work_hours 合計 vs 到達 avg_score | 15 時間以内で目標到達 |
| H6 | input_profile（接続形式の組合せ）と avg_score/tag_dist の対比（専門家横断） | 記述的分析（n が小さいため統計検定はしない） |

注意：専門家 3〜5 名・評価 25 件では統計的検出力が低い。数値は「傾向」として報告し、減点タグと自由コメントの定性分析を併記する。

## 3. 評価セット運用
- eval_sets は準備期間に生成→ operator が品質確認・編集→ `locked`。以後、追加・変更・削除は不可（監査用に編集履歴を残す）。
- 評価用 consultations は学習用 Organize の入力に決して含めない（Organize のクエリで `is_eval = false` を強制。テストで担保）。
- 「自分ならこう答える」（evaluations.my_answer）は評価セットの相談に対する本人回答。Organize 入力に含めると評価セットのリークになるため、【仮置き：論点#9 / D-13】PoC では学習に使わず、ブラインド比較の「本人回答」としてのみ使用する。

## 4. ログ要件
- 各 agent_answer：model, prompt_version, vault_snapshot_id, top_k, retrieved ids（notes/chunks）, tokens_in/out, latency_ms, cost_usd
- 各 organize 実行：入力 chunk 数、入力 answer 数、生成ノート数（new/updated/deleted）、conflicts 数、所要、コスト
- 各 transcribe：provider, duration_sec, cost, edit_ratio
- 上記を O04 ジョブ画面と S07/O01 の集計に使う。

## 5. レポート出力
- operator が「Batch レポート」を生成（Markdown）：指標表、グラフ画像（S07 と同じ）、減点タグ上位、代表的な失敗回答 3 件と原因ノート、次 Batch への推奨投入。
- 最終判定レポート：Go / Pivot / Stop の判断材料（1 の指標＋H5 のコスト）。
